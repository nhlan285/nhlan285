# 🏗️ How I Like to Build Software

I'm gradually developing a preference for applications with clear boundaries.

```text
UI
│
├── State Management
│
├── Domain / Business Logic
│
├── Repository
│
├── API / Data Source
│
└── Backend / External Services
```

For mobile applications, I care about:

- predictable state
- typed data models
- reusable API layers
- useful error handling
- separating UI from data access
- maintainable project structure
- mockability
- avoiding unnecessary complexity

I still have a lot to learn, but I prefer understanding **why an architecture exists** rather than copying patterns blindly.
